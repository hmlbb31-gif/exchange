## 1. Что это за проект

Telegram-бот-**обменщик** для сайта mangabuff.ru. Автоматически рассматривает
входящие обмены и принимает **только выгодные и безопасные** по строгим
(fail-closed) правилам. Работает на собственных аккаунтах владельца («твинках»),
поэтому открытые куки — это норма, чужие куки НЕ собираются.

> Проект `farm/` (бот-фарм) намеренно НЕ трогаем — вне текущей задачи.

Стек: Python 3.12/3.13, `httpx` (ядро), `aiogram` 3.13 + `cryptography` (бот),
`pytest` (тесты). Хранилище — SQLite (`data/trade.sqlite3`, создаётся сама).

## 3. Что было сделано в этой ветке (хронологически)

### 3.1. Починка структуры (было сломано)
Репозиторий пришёл «флэттенизированным»: модули ядра лежали в корне, но код
импортировал их как `from mb.*` — **пакета `mb/` не было, ничего не запускалось
из чистого клона**. Также в git попал мусор: десятки `.pyc`, кэш pytest
(`CACHEDIR.TAG`, `lastfailed`, `nodeids`), `.gitignore` состоял из одного `*`
(глушил все новые файлы), а `README.md` был перезаписан заглушкой pytest.

Исправлено:
- Ядро собрано в пакет `mb/`, тесты → `tests/`, данные → `data/`.
- Удалён весь закоммиченный мусор; написаны нормальные `.gitignore`,
  `pyproject.toml` (резолвинг `mb`+`config`, `testpaths`), человеческий `README.md`.
- Проверено end-to-end: `run_dry.py` грузит ~376k рангов и доходит до HTTP.

### 3.2. Улучшения движка решений (`mb/decision.py`, `config.py`, `mb/market.py`, `mb/cards.py`)
Все — с дефолтами, сохраняющими старое поведение; покрыты новыми тестами.

- **Per-rank пороги выгоды** — `Rules.min_gain_ratio_by_rank: dict[str,float]`.
  Для обмена берётся самый строгий порог среди ОТДАВАЕМЫХ карт (helper
  `required_ratio`). Дешёвый мусор можно смягчить, ценные ранги — ужесточить.
- **Анти-разбавление корзины** — `Rules.basket_guard_ratio` (по умолч. 1.0).
  Лучшая отдаваемая карта должна быть покрыта полученной сопоставимого веса.
  Ловит «слил ценную B в куче мусора E», когда сумма формально проходит.
- **Защита косметики** — `Rules.protect_palindrome` (вкл.) режет отдачу карт с
  палиндромным номером (метка берётся из разметки сайта
  `card-copy-ribbon--palindrome`, не эвристика). `Rules.protect_copy_number_below`
  (по умолч. 0/выкл.) бережёт ранние копии.
- **Доверие к рыночной цене** — `CardStore(price_min_samples=...)` +
  `MarketTracker.reference_price(card_id, min_samples)`: цена возвращается только
  если данных не меньше порога, иначе None → fail-closed SKIP (защита от
  демпинга/накрутки одним лотом). Связь рынок→цена уже была в `CardStore.get`.

### 3.3. Кнопочный Telegram-бот (`bot.py`) — полностью переписан
Управление **без команд**: `/start` → инлайн-кнопки.
- **🔗 Привязать аккаунт** — прислать строку cookie одним сообщением; бот
  валидирует её живым заходом на `/trades`, удаляет сообщение с кукой из чата,
  шифрует (Fernet) и сохраняет в БД. Кука переживает рестарт → `.env`/`cookies.txt`
  больше не обязательны. Есть **горячий перезапуск воркера** при смене куки.
- **🧪/🟢 Переключатель Сухой ⇄ LIVE** — прямо в меню, с предупреждением при LIVE.
- **🛡 Whitelist** — список защищённых карт + добавить/убрать по id (пробел/запятая).
  Сразу подхватывается движком (`app.reload_protected()`).
- **⚙️ Правила** — каждое числовое поле редактируется кнопкой (нажал → прислал
  число). Тумблер защиты палиндромов. Список полей — в `RULE_FIELDS`/`RULE_LABELS`.
- **🕵️ User-Agent** — просмотр/смена UA (важно: UA должен совпадать с браузером,
  откуда взята кука, иначе DDoS-Guard сбросит сессию).
- **🔄 Один проход / 📊 Статус / 📈 Статистика**.

### 3.4. Персистентность настроек (`mb/storage.py`)
Добавлена таблица `settings (key, value)` + методы `get_setting/set_setting/
all_settings`. При старте `ExchangeApp._load_settings()` восстанавливает dry_run,
user_agent, protect_palindrome и все числовые правила. Проверено «рестартом».

## 4. Ключевые точки в коде (куда смотреть)

- **Бизнес-логика приёма обмена:** `mb/decision.py → evaluate_trade()`.
  Порядок проверок = порядок вето (whitelist → защищённый ранг → палиндром/копия
  → неизвестный ранг → дорогая без цены → популярная(ПП) → анти-разбавление →
  порог выгоды). Всё fail-closed: сомнение → SKIP/REJECT, не ACCEPT.
- **Пороги и режимы:** `config.py` → классы `Config` (dry_run, user_agent, cookie)
  и `Rules` (все пороги). Редактируемые из ТГ поля перечислены в `bot.RULE_FIELDS`.
- **Роутинг ввода в боте:** `bot.ExchangeApp.awaiting: dict[uid, kind]`, где kind ∈
  {`cookie`, `ua`, `wl_add`, `wl_del`, `rule:<name>`}; обрабатывается в `_on_text`.
- **Цикл обмена и уведомления:** `mb/worker.py → TradeLoop`.

## 5. Как запустить

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements-bot.txt        # Python 3.12/3.13
cp .env.example .env                        # EXCHANGE_BOT_TOKEN, ADMIN_IDS, FERNET_KEY
python bot.py
```
Дальше в Telegram: `/start` → «Привязать аккаунт» → вставить cookie → включить обмен.

Диагностика без телеграма: `python run_dry.py` (использует куку из `.env`/`cookies.txt`).

Тесты: `pytest -q` (ожидается 72 passed, 1 skipped).

## 7. Важные замечания / подводные камни

- **`.env` и `cookies.txt` лежат в git** (оставлены намеренно — это твинки). Если
  репозиторий не приватный на 100% — убрать: `git rm --cached .env cookies.txt`.
- **FERNET_KEY** — если не задан, кука в БД пишется открытым текстом (бот
  предупреждает при привязке). Задать: `python -c "from cryptography.fernet import Fernet;print(Fernet.generate_key().decode())"`.
- **User-Agent должен совпадать** с браузером, откуда экспортирована кука
  (DDoS-Guard привязывает сессию к UA). Меняется кнопкой 🕵️ в меню.
- **Fail-closed — это фича, не баг.** Если движок делает SKIP при нехватке данных
  (нет ранга/цены) — так и задумано; не «чинить» ослаблением проверок.
- **Farm-проект не трогать** без отдельной задачи.
