# Как организовано понимание рынка

Коротко: у mangabuff нет API и нет истории цен — страница показывает только
**текущие** активные лоты и заявки. Поэтому «понимать цену» = периодически
снимать снимки рынка и строить историю самим. Реализовано в `mb/market.py`.

## Что откуда берём (эндпоинты)

| Сигнал | Запрос | Что парсим |
|---|---|---|
| Активные лоты карты | `GET /market/card/{id}` | блоки `.market-show__item`, `lot_id` из «Купить» `/market/{lotId}`, цена в S из ценового футера |
| Заявки (спрос) | `GET /market/requests?card_id={id}` | `.manga-cards__item.market-item` |
| «Хочу» (спрос) | `GET /cards/{id}/offers/want` | `.card-offer-panel` |
| Ранг карты | `GET /cards` (каталог) | `data-rank` + `data-card-id` |

Лот бывает **за S** (цена, напр. «8 S») или **бартер** (карта-за-карту). Для
денежной оценки берём только S-лоты. Чтобы не спутать «8 S» (цена) с «3 S» (три
карты ранга S в бартере), цену читаем **только из явного ценового контейнера**
лота, а не из любого текста «N S». Сомнение → лот считается бартером (fail-closed).

## Как строим историю цен (главная идея)

Сайт не хранит «продано за сколько». Мы выводим это сами:

1. Каждый снимок: запоминаем набор активных `lot_id` и их цены (таблица `active_lots`).
2. На следующем снимке лот, который **исчез**, считаем **проданным** по последней
   виденной цене → пишем в `sold_events`.
3. Так, без API, набирается ровно то, что показывает твой дашборд по «Химено»:
   проданные лоты, средняя / минимальная / последняя цена, динамика во времени.

Заявки обрабатываются так же: исчезнувшая заявка ≈ выполненная сделка спроса.

## Опорная (reference) цена карты

`reference_price(card_id)`:
1. если есть активные S-лоты → **медиана** их цен (устойчива к single-выбросу),
2. иначе → **средняя цена продаж** из истории,
3. иначе → `None` → движок обмена делает **SKIP** (не оцениваем вслепую).

Медиана, а не минимум: один демпинговый лот не должен ронять оценку карты.

## Сигнал «ПП» (популярная карта)

Популярность — это спрос, а не только цена. `is_popular()` считает карту ПП, если:
- много «Хочу» **и** мало активных лотов (высокий спрос при дефиците), или
- «Хочу» выше порога сам по себе, или
- много заявок.

Пороги — в `config.py → Rules` (`pp_want_threshold`, `pp_low_supply_lots`,
`pp_request_threshold`). ПП-карта в отдаваемых → обмен REJECT, даже если ранг низкий.

## Как это подключено к обменнику

`Trader._enrich()` перед оценкой каждого трейда снимает свежий снимок рынка по
всем участвующим картам и кладёт в `MarketTracker`. `CardStore.get()` отдаёт
движку `CardInfo` с рангом + reference-ценой + сигналами спроса. Дальше решает
`mb/decision.py`.

## Расписание сэмплирования (рекомендация)

- **Карты из активных трейдов** — снимок прямо перед решением (уже так).
- **Твой инвентарь / ватчлист** — фоновый сэмплер раз в 10–15 мин, чтобы копить
  историю и ловить продажи. Общий token-bucket с обменником, низкий приоритет,
  чтобы не жрать лимит запросов.
- Чем чаще снимки, тем точнее «продано за сколько», но выше нагрузка. 10–15 мин —
  разумный компромисс (как в `FEATURES_PLAN` монитора).

## Что ещё нужно добить на живых данных

- Точный **ценовой селектор** S-лота на `/market/card/{id}` (подтвердить на карте,
  которая продаётся за S, — у тестовой «Илеон» были только бартерные лоты).
- Разметку **заявок** и **«Хочу»** на непустых картах (сейчас считаем по числу
  панелей — достаточно для сигнала спроса, но стоит сверить).
